# 大模型应用部署指南

## 部署平台选择

Vercel 适合部署 Next.js 应用，免费层支持 Serverless 函数，冷启动时间在数百毫秒。国内访问 Vercel 速度不稳定时，可考虑阿里云函数计算或自有服务器。Docker 容器化是自建部署的标准方式，镜像需注意精简体积以加快拉取速度。部署前确认目标地区的数据合规要求，模型 API 的调用链路需要考虑跨境延迟。

## Serverless 注意事项

Serverless 函数有执行时长与内存上限，长耗时任务应拆分为异步任务或队列处理。数据库连接池在 Serverless 环境下容易耗尽，推荐使用托管数据库的连接池能力。文件系统不可持久化，上传文件需转发到对象存储。冷启动会放大依赖加载时间，重型依赖建议按需动态导入。

## 流式输出

SSE（Server-Sent Events）是实现大模型流式输出的常用方案，比 WebSocket 更轻量。前端通过 AbortController 取消请求，用户切换问题时主动中断连接，避免无效请求堆积。长连接需设置心跳与超时，防止代理层误断。流式回答在完整生成后落库，页面刷新时从数据库恢复历史对话。

## 成本控制

Token 成本是大模型应用的主要开销，可通过缓存高频问题、限制上下文长度、使用更便宜的模型处理简单任务来控制。Embedding 调用建议批量处理，减少网络往返次数。长对话的上下文压缩能显著降低单次请求成本，摘要与向量记忆是两种互补的压缩手段。

## 安全防护

模型输出属于不可信内容，前端渲染时必须做 XSS 清洗。Prompt 注入防护包括：将用户输入与系统指令隔离、限制工具调用参数、对敏感操作增加人工确认。API Key 必须存放在服务端环境变量中，禁止出现在前端代码。生产环境建议接入限流与审计日志，异常调用模式及时告警。

## 监控与运维

上线后需要监控模型调用延迟、错误率与 token 消耗。问答系统的检索质量会随知识库变化漂移，建议定期运行评测集做回归。日志系统记录请求链路，检索无结果与低相似度查询单独统计，作为知识库补全的依据。

## 环境变量管理

本地开发使用 .env.local，部署平台使用其环境变量面板，密钥不进代码仓库。数据库连接串按环境隔离，开发环境与生产环境使用不同的库实例。密钥轮换时需同步更新所有部署环境，并在轮换后验证服务可用性。

## 灰度与回滚

大模型应用建议灰度发布，先切 10% 流量观察错误率与用户反馈。提示词变更影响面大，应通过配置中心管理并支持快速回滚。模型版本升级需在评测集上回归，确认答案质量没有明显下降后再全量放开。
